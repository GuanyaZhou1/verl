  ┌──────────────────────────────────────┬──────────┬───────────────────────┐
  │                 配置                 │ 作用位置 │         作用          │
  ├──────────────────────────────────────┼──────────┼───────────────────────┤
  │ custom_reward_function.reward_kwargs │ Reward   │ 计算 final_score =    │
  │ .*_weight                            │ 函数内   │ Σ(weight × score)     │
  ├──────────────────────────────────────┼──────────┼───────────────────────┤
  │ algorithm.gdpo.reward_weights        │ GDPO 优  │ 加权合并各组件的归一  │
  │                                      │ 势估计器 │ 化优势                │
  └──────────────────────────────────────┴──────────┴───────────────────────┘

  工作流程对比：

  GRPO (当前默认):
  answer_score, bbox_score, ... → reward_kwargs权重加权求和 → final_score →
  组内归一化 → advantage

  GDPO:
  answer_score → 组内归一化 → A_answer ─┐
  bbox_score   → 组内归一化 → A_bbox   ─┼→ gdpo.reward_weights加权求和 → A_sum →
   batch归一化 → advantage
  format_score → 组内归一化 → A_format ─┘

  关键区别：
  - GRPO: 使用 reward_kwargs 权重计算的 final_score
  - GDPO: 直接使用各 *_score 组件，忽略 reward_kwargs 中的权重，改用
  gdpo.reward_weights

  建议：
  如果使用 GDPO，可以将 reward_kwargs 中的权重都设为
  1.0（或保持默认），因为它们计算的 final_score 不会被使用。真正的权重应该在
  algorithm.gdpo.reward_weights 中配置。

● NWD (Normalized Wasserstein Distance) 机制详解：

  核心公式

  基于论文 "A Normalized Gaussian Wasserstein Distance for Tiny Object 
  Detection"

  NWD = exp(-normalized_dist × adaptive_constant)

  其中：
  # 1. 将 bbox 建模为 2D 高斯分布
  #    μ = (center_x, center_y), σ = (width/2, height/2)

  # 2. 计算 2D Wasserstein Distance (闭式解)
  center_dist² = (pred_cx - gt_cx)² + (pred_cy - gt_cy)²
  size_dist² = ((pred_w - gt_w)² + (pred_h - gt_h)²) / 4
  wasserstein = √(center_dist² + size_dist²)

  # 3. 用 GT 对角线归一化
  normalized_dist = wasserstein / gt_diagonal

  # 4. 自适应常数 (大目标严格，小目标宽松)
  relative_size = gt_diagonal / image_diagonal  # 0~1
  adaptive_constant = constant × (1.0 - 0.5 × relative_size)

  # 5. 指数映射到 [0, 1]
  NWD = exp(-normalized_dist × adaptive_constant)

  NWD vs IOU 对比

  ┌────────────────┬────────────────┬──────────────┐
  │      特性      │      IOU       │     NWD      │
  ├────────────────┼────────────────┼──────────────┤
  │ 小目标位置偏移 │ 严重惩罚       │ 宽松         │
  ├────────────────┼────────────────┼──────────────┤
  │ 无重叠框       │ 直接 0 分      │ 仍有梯度信号 │
  ├────────────────┼────────────────┼──────────────┤
  │ 尺度敏感性     │ 对小目标不友好 │ 尺度不变     │
  └────────────────┴────────────────┴──────────────┘

  当前实现

  代码中 metric="nwd" 实际已改用 自适应 IOU：
  if metric == "nwd":
      # 小目标: √IOU (宽松)
      # 大目标: IOU² (严格)
      return compute_adaptive_iou(iou, gt_area)

  原始 compute_nwd() 函数仍存在但未被使用。

  配置参数

  BBOX_METRIC=${BBOX_METRIC:-iou}      # "iou" 或 "nwd"
  NWD_CONSTANT=${NWD_CONSTANT:-2.0}    # 常数越大越宽松

● 已修复。在 protocol.py 的 concat 方法中添加了对不同维度数组的处理：

  try:
      non_tensor_batch[key] = np.concatenate(val, axis=0)
  except ValueError:
      # Fallback: 合并为 1D object 数组
      total_len = sum(len(v) for v in val)
      result = np.empty(total_len, dtype=object)
      idx = 0
      for v in val:
          for item in v:
              result[idx] = item
              idx += 1
      non_tensor_batch[key] = result

  这样当遇到维度不一致的数组（如 bbox_details、segment_details）时，会自动合并为
   1D object 数组。
